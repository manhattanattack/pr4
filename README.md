# Практическая работа №4

Продолжение [ПР3](https://github.com/manhattanattack/pr3). Добавлены четыре вида противников по методичке «ММ Пр4».

## Что добавлено

- `BaseMob.js` — общий класс мобов.
- `TankMob.js` — танк: 250 HP, защита спереди, сильный удар с замахом.
- `SprinterMob.js` — быстрый моб: 20 HP, зигзаг и отскок после атаки.
- `BlindMob.js` — слепой моб: слышит шаги и выстрелы, не слышит движение на Ctrl.
- `KamikazeMob.js` — камикадзе: через секунду после остановки взрывается и наносит 50 урона в радиусе 3.5 м.
- `MobManager.js` — создаёт мобов и обновляет их на сервере.
- `NetworkMobVisual.cs`, `ClientMobManager.cs` — отображение мобов в Unity.
- `NetworkMob.prefab` — в нём четыре вида моделей, щит танка, антенна слепого моба и полоска HP.
- `GameScene.unity` и `NetworkClient.cs` — подключены все сетевые события.

Броня танка коротко мигает при блокировании урона. Перед взрывом камикадзе мигает красным.
После смерти моба появляется небольшой куб `Loot_<архетип>` соответствующего цвета.
Это **пример выпадения лута по архетипу**: подбор и инвентарь в методичке не описаны, поэтому их не добавлял.

## Запуск

1. Открыть проект в Unity Hub (Unity 6000.4.6f1), дождаться импорта.
2. Открыть `Assets/Scenes/LobbyScene.unity`.
3. В папке `Assets/MazeServer` запустить `npm install` (если нужно), затем `node server.js`.
4. Запустить игру через лобби. Для проверки сетевой игры нужен второй клиент.

Отдельные команды для сборки сцены **не нужны**: `GameScene` и `NetworkMob.prefab` уже сохранены в репозитории.

## Что проверить в Unity

- В GameScene видны четыре разных вида мобов и полоски HP.
- Танк не получает урон в лоб, но получает со спины и отбрасывает игрока.
- Спринтер атакует и отскакивает; гибнет от одного удара/выстрела.
- Слепой моб реагирует на шум, но не реагирует на тихое движение с Ctrl.
- Камикадзе мигает 1 секунду и взрывается.
- После гибели моба появляется куб лута.

## Важно про картинки и шрифты

У проекта из ПР2 часть `.png` и `.ttf` хранится через Git LFS. При копировании репозитория через API сами LFS-объекты не переносятся. В этом репозитории есть GitHub Actions **Transfer original Git LFS files from PR2 to PR4**: при необходимости откройте Actions, выберите эту команду и нажмите Run workflow. Это перенос ресурсов, **не сборка Unity-сцены**.

Клонировать лучше через GitHub Desktop с установленным Git LFS. Простая загрузка ZIP может не скачать бинарные LFS-файлы.
